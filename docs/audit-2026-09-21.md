# Full Stack File Vault audit — 2026-09-21

## Scope and conclusion

Reviewed the application boundaries and deployment configuration, ran the repository's
backend/database/browser suites, and exercised the local HTTPS application, encrypted
backup restoration, and temporary PostgreSQL-backed demo. This is an evidence-based
local audit, not a guarantee that every line is defect-free or a production certification.
Generated code was regenerated and checked for stability rather than manually audited
line by line. No real cloud resources or Kubernetes workloads were deployed.

  This pattern scan is not an exhaustive secret-detection service.

## Remaining limits and release work

- Public Render URL, managed-provider database privileges, real TLS/domain routing,
  provider lifecycle behavior and account billing settings are not verified by local
  emulation. The demo is temporary, not a durable production deployment.
- Kubernetes manifests render, but no cluster rollout or storage-driver qualification
  was performed in this audit. External database, secrets, ingress/DNS and network
  restrictions still require environment-specific configuration.
- Production external object storage remains a documented target, not an implemented
  S3 adapter. The production storage path currently uses durable Linux filesystem storage.
- Backups were restored to an isolated database and their file bytes verified. A fully
  restored browser deployment, off-host encrypted upload/retrieval, and measured RPO/RTO
  remain untested. Do not equate archive verification with complete disaster recovery.
- Local Prometheus scrapes/rules work; alert delivery to an actual receiver remains untested.
- Concurrent/race tests passed, but sustained multi-user load, low-memory stress at
  maximum simultaneous transfer sizes, power-loss testing, and infrastructure failure
  drills remain outstanding.
- Browser coverage is Chromium plus automated accessibility/keyboard checks, not
  exhaustive browser or manual screen-reader certification.
- The UI upload limits match the shipped normal/demo configurations. Arbitrary operator
  changes to backend limits are not dynamically advertised to the frontend.
- Administrative audit is implemented; comprehensive upload/download/delete activity
  auditing and optional assignment features remain separate work in acceptance.md.

## Hosted CI follow-up

Commit 3a8fa6f passed the hosted Go stage, but the browser suite exposed a quick-reload issue: session restoration could receive RATE_LIMITED and incorrectly display the sign-in screen. The client now shares session restoration across effect mounts and makes at most three attempts, waiting one second only after rate-limit rejection. The server's two-calls-per-second limit is unchanged; uploads and other mutations are not automatically replayed. Typechecking and all six local browser scenarios passed, including deterministic rejection of Bootstrap and Identity during reload. The follow-up hosted run is required before deployment.
